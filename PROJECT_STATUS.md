## Архитектура и неизменяемые решения

- `remote/` (Kotlin/Compose) ⇄ MQTT ⇄ `app/` (Android Java/Kotlin) ⇄ Bluetooth ⇄ установленный Arduino; `core/` — общие протокол/Auto-правила. ESP32 отсутствует; историческая прошивка в `archive/firmware-not-used/` неактивна.
- Android 6+ (`minSdk 23`); Android 4/5 и Legacy исключены. JDK 17, Gradle 8.9, AGP 8.7.3, Kotlin 2.2.21.
- Команды Arduino по подтверждённому протоколу: `a0\\0` manual, `a1\\0` PID, `a3\\0` STOP, `kNN\\0` температура 0–100, `vNN\\0` мощность 0–100; `p/i/d/z` — параметры PID ×100. `\\0` — **буквальные** backslash и 0, не NUL. Телеметрия `|...|end`. Не отправлять `x1`, `x0`, `h`.
- Android Auto исполняется на телефоне, не через Arduino `a2`: один `a1\\0` на старте, далее `kNN\\0` на этапах; таймер начинается после свежей телеметрии `mode=1` с подтверждённой уставкой. Не ломать существующие JSON Auto-программ.
- **Риск безопасности:** у установленного Arduino нет watchdog на потерю Android/Bluetooth. При обрыве связи `a3\\0` может не дойти, а последняя PID-уставка сохраниться. Не считать Auto безопасным без наблюдения.
- Не менять Arduino/протокол, application IDs, подпись обновления или `main` без прямого разрешения. Не смешивать рефакторинг, редизайн и исправление связи в одну поставку. Версию приложения повышать только при изменении APK/поведения, не за одну документацию.
