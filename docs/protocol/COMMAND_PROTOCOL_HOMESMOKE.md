# HomeSmoke — проверенный Bluetooth-протокол

Источник: оригинальный проект MIT App Inventor `Homesmoke.aia`, файл `Screen1.bky`. Проверены все вызовы `BluetoothClient.SendText`.

## Активные исходящие команды

| Действие | Фактически отправляемый текст | Условие / источник |
|---|---|---|
| Ручной режим | `a0\0` | `Okno_RejimRuk`, только при подключенном `BTclient`; также `rejim_rabot=0` |
| Режим ПИД | `a1\0` | `Okno_RejimPID`, только при подключенном `BTclient`; также `rejim_rabot=1` |
| Авто режим | `a2\0` | `Okno_RejimAvto`, только при подключенном `BTclient`; также `rejim_rabot=2` |
| Задать температуру в ПИД-режиме | `k<значение>\0` | `Dialogs1.AfterTextInput`; значение 0..100; отправляется при `rejim_rabot==1` |
| Задать мощность в ручном режиме | `v<значение>\0` | `Dialogs1.AfterTextInput`; значение 0..100; отправляется при `rejim_rabot==0` |
| Изменить kP | `p<kP*100>\0` | `Button_kP.Click`; BT подключен, поле не пустое |
| Изменить kI | `i<kI*100>\0` | `Button_kI.Click`; BT подключен, поле не пустое |
| Изменить kD | `d<kD*100>\0` | `Button_kD.Click`; BT подключен, поле не пустое |
| Изменить zP | `z<zP*100>\0` | `Button_zP.Click`; BT подключен, поле не пустое |

Пример: при вводе `2.35` в поле `kP` приложение вычисляет `2.35*100 = 235` и отправляет `p235\0`.

## Отключенный блок

В процедуре `Okno_configPID` присутствует блок `SendText("a" + "3" + "\\0")`, то есть `a3\0`, но этот конкретный блок в исходном `.aia` помечен `MANUALLY_DISABLED`. Поэтому действующая старая программа его **не отправляет**. В новую версию команда `a3\0` не переносится как активная без отдельного подтверждения.

## Окончание команды

В блоках App Inventor строка `\0` хранится как два символа: обратная косая черта (`0x5C`) и цифра ноль (`0x30`). Это не байт NUL `0x00`.

## Входящий пакет

`Clock1.Timer` читает все доступные байты через `ReceiveText`, накапливает их в `global buffer`, ждёт наличие `end`, затем делит весь буфер по `|`. Индексы App Inventor 1-based:

- поле 2 — `BLTempDS`
- поле 3 — температура щупа K (`LTempTipK`)
- поле 4 — `Т° к`
- поле 5 — `Т° п`
- поле 6 — мощность ТЭНа, %
- поле 7 — режим работы
- поле 8 — статус / служебное поле (`Label24`)
- поле 9 — `kP`
- поле 10 — `kI`
- поле 11 — `kD`
- поле 12 — `zP`
- поле 13 — температура щупа T (`LTempTipT`)

## PID-экран

Исходный экран `Okno_configPID` содержит по отдельности:

- `Label_kP` + `TextBox_kP` + `Button_kP`
- `Label_kI` + `TextBox_kI` + `Button_kI`
- `Label_kD` + `TextBox_kD` + `Button_kD`
- `Label_zP` + `TextBox_zP` + `Button_zP`

Каждая зелёная кнопка с галочкой отправляет только соответствующий коэффициент.

## Профиль установленного контроллера

Пока Arduino нельзя перепрошить, HomeSmoke работает только с ранее подтверждённым старым протоколом:

- Android Auto выполняет этапы, время и условия K/T на телефоне;
- при запуске программы один раз отправляются `a1\0` и `k<уставка>\0`;
- при смене этапа отправляется только `k<уставка>\0`;
- старый встроенный Arduino Auto `a2\0` приложением не используется;
- команды новой ревизии `x1\0`, `x0\0` и `h\0` не отправляются;
- STOP выполняется подтверждённой командой режима `a3\0`;
- применение PID и уставки проверяется по полям режима и уставки в следующей телеметрии Arduino.

Ни одна новая команда не добавляется без подтверждения исходным `.aia`, кодом фактически установленного контроллера или отдельным решением владельца устройства.
