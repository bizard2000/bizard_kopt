# Журнал решений HomeSmoke

Этот файл хранит решения, которые должны переживать переходы между чатами. Новые решения добавляются отдельными пунктами; старые не переписываются без объяснения причины.

## D-001 — Две отдельные программы

HomeSmoke (`app`) напрямую работает с Arduino по Bluetooth и служит MQTT-шлюзом. HomeSmoke Remote (`remote`) работает через MQTT. Их package id, версии и жизненные циклы независимы.

## D-002 — Активная ветка

Разработка и CI выполняются в `homesmoke-native`. Ветка `main` не изменяется и не объединяется без прямого разрешения владельца.

## D-003 — ESP32 не относится к этому проекту

В фактической схеме HomeSmoke нет ESP32. Найденные PlatformIO/ESP32-файлы перемещены в `archive/firmware-not-used` только для сохранения истории и не являются частью Android-сборки.

## D-004 — Установленная Arduino неизменна

Arduino сейчас нельзя перепрошить. Приложения обязаны подстраиваться под фактически установленную старую прошивку. `archive/firmware-not-used/arduino/HomeSmoke_Controller_rev_2_0_AndroidAuto.ino` не установлена на устройстве.

## D-005 — Подтверждённый старый протокол

- `a0` — ручной режим;
- `a1` — PID;
- `a2` — старый встроенный Auto Arduino, приложением не используется;
- `a3` — STOP;
- `kNN` — целая уставка камеры 0–100 °C;
- `vNN` — целая ручная мощность 0–100%;
- `pNN`, `iNN`, `dNN`, `zNN` — коэффициенты с масштабом ×100;
- терминатор команды — два буквальных символа `\\0`;
- телеметрия — кадр `|...|end` по карте из документа протокола.

Команды `x1`, `x0`, `h` относятся к неустановленной ревизии и не отправляются.

## D-006 — Auto выполняется Android-приложением

Рецепт, до четырёх этапов, выдержка, допуск и условия K/T вычисляются телефоном. При старте Auto один раз отправляется `a1`, затем уставка `kNN`. На переходах отправляется только новая `kNN`. Отсчёт этапа начинается/продолжается только после свежего подтверждения `mode=1` и нужной уставки.

## D-007 — Безопасность при потере Bluetooth

Старая Arduino не имеет watchdog Android-связи. После физического обрыва Bluetooth телефон не может доставить `a3`; контроллер может удерживать последнюю PID-уставку. До отдельного аппаратного решения Auto нельзя оставлять без наблюдения.

## D-008 — Поддерживаемые Android-версии

Обе активные программы поддерживают Android 6+ (`minSdk 23`, `targetSdk 35`). Android 4/Legacy и Android 5 не возвращаются в активную сборку.

## D-009 — Kotlin и Compose

Remote полностью переведён на Kotlin и использует Compose-интерфейс. HomeSmoke 2.6.13 стал первой сборкой с Kotlin, но основная часть HomeSmoke пока остаётся Java; Kotlin используется в диагностике. Миграцию HomeSmoke продолжать постепенно после полевого теста.

## D-010 — Версии и история

Функциональное изменение или изменение интерфейса требует нового `versionCode`, новой patch-версии и записи в `CHANGELOG.md`. Документация/CI без изменения APK версию не повышают. Отображаемая версия всегда берётся из package metadata/`BuildConfig`, а не из вручную записанной строки.

## D-011 — Резервная сборка

HomeSmoke 2.5.0 сохраняется как rollback. Более старые бинарники можно удалить из вершины ветки, поскольку они остаются в Git-истории.

## D-012 — Стабилизация перед новым редизайном

Текущие версии сначала проходят реальный тест. Следующий большой редизайн или архитектурная миграция запрещены до разбора фактического журнала HomeSmoke/Remote.
