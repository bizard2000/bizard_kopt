# HomeSmoke 2.6.16 — профиль установленной Arduino

## Причина выпуска

Arduino в реальном устройстве не перепрошивалась и сейчас не может быть обновлена. Поэтому HomeSmoke больше не отправляет команды `x1`, `x0` и `h`, добавленные для подготовленной, но не установленной ревизии контроллера 2.0.

## Архитектура Auto

- Рецепт, до четырёх этапов, выдержка, допуск и условия по щупам K/T выполняются Android-приложением.
- Встроенный старый режим Arduino `a2` не используется.
- При старте Android Auto отправляет `a1`, затем `k<температура камеры>`.
- При смене этапа отправляется только новая команда `k<температура камеры>`.
- Завершение, пользовательская остановка и ошибка датчика отправляют `a3`.

## Подтверждение доставки

После старта и каждой смены этапа HomeSmoke ждёт свежую телеметрию с `mode=1` и требуемой уставкой камеры. Команда `a1` отправляется только один раз при запуске Auto; при отсутствии подтверждения повторяется только `k<температура камеры>`, но не более трёх отправок уставки. До подтверждения выдержка этапа не отсчитывается. После исчерпания попыток Auto останавливается и отправляет `a3`.

Старая прошивка не имеет Android-watchdog. При физической потере Bluetooth приложение уже не может доставить STOP, поэтому Arduino может сохранить последнюю PID-уставку. Это ограничение явно показано в библиотеке программ; работу нельзя оставлять без контроля.

Полевой журнал записывает `BT_TX`, `BT_TX_ERROR`, `AUTO_COMMAND_PENDING`, `AUTO_COMMAND_ACK`, `AUTO_COMMAND_RETRY` и `AUTO_COMMAND_FAILED`.

## Не изменено

- прошивка Arduino;
- буквальный терминатор `\\0`;
- формат телеметрии `|...|end`;
- MQTT-поля HomeSmoke Remote;
- JSON-формат библиотеки Auto-программ;
- логика этапов, допуска и условий K/T.
