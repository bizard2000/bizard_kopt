# Ревизия HomeSmoke, Remote и GitHub — 9 сентября 2026

## Итог

HomeSmoke 2.6.16 и HomeSmoke Remote 2.4.6 собираются и проходят 33 автоматических теста. Последняя полная CI-сборка до уборки репозитория завершилась успешно и опубликовала оба APK. Блокирующей ошибки исходного кода не обнаружено. Главный незакрытый этап — проверка на реальной Arduino, Bluetooth и MQTT.

Репозиторий до ревизии был технически работоспособен, но плохо передавал контекст: отсутствовал обычный `README.md`, не было единого статуса/истории, активные Android-модули лежали рядом с неиспользуемыми ESP32/Arduino rev2, в `ci/` оставались одноразовые patch-скрипты, а `dist/` занимал около 258 МБ и содержал пары дублирующихся APK/BIN и 46-МБ build log.

## Проверено

- версии, package id, min/target/compile SDK и Java/Kotlin toolchain;
- Android manifests, exported-компоненты и разрешения;
- Bluetooth → телеметрия → Android Auto → MQTT в HomeSmoke;
- MQTT-команды и ACK-индикация в Remote;
- карта установленного Arduino-протокола;
- unit/Robolectric/Compose-тесты и GitHub Actions;
- структура веток, релизов, тегов и артефактов GitHub;
- хранение MQTT-пароля и политика подписи APK.

## Найденные риски

| Приоритет | Риск | Решение |
|---|---|---|
| P0 | Подтверждённых блокирующих дефектов нет | Не начинать новый редизайн до полевого теста |
| P1 | Реальные Bluetooth/Arduino/MQTT сценарии не покрываются CI | Выполнить полевой тест и сохранить ZIP-журнал |
| P1 | Remote не завершает локальное ожидание, если ACK полностью потерян | Добавить отдельный тайм-аут pending-команды после полевого теста |
| P1 | MQTT Remote не контролирует возраст PINGRESP/входящих пакетов | Добавить keepalive timeout по образцу HomeSmoke |
| P1 | Remote построен слоями `MainActivity` → `GraphUxActivity` → `GraphUxFixActivity` с рефлексией и Compose overlay | После стабилизации объединить state/UI без одномоментной потери функций |
| P1 | Debug keystore и известный пароль находятся в публичном репозитории | Не менять молча; подготовить migration-план production-подписи, иначе обновление поверх установленного APK перестанет работать |
| P2 | `android:usesCleartextTraffic="true"` разрешает незашифрованный MQTT | Оставлено ради локальных брокеров; в UI рекомендовать TLS для внешней сети |
| P2 | Нет Gradle Wrapper | Добавить wrapper отдельным инфраструктурным изменением после полевого теста |
| P2 | Ветки `main` и `homesmoke-native` не защищены, тегов и GitHub Releases нет | После подтверждения устройства добавить protection/tag/release |
| P2 | CI имеет `contents: write` и сам коммитит APK в рабочую ветку | Позже разделить test/build и publish permissions |
| P2 | HomeSmoke пока не полностью на Kotlin | Продолжать послойно, начиная с малых классов после 2.6.16 field test |

## Что приведено в порядок

- Создан корневой `README.md` с фактической архитектурой.
- Созданы единый `PROJECT_STATUS.md`, `CHANGELOG.md`, `AGENTS.md` и журнал решений.
- Документы собраны в `docs/` с индексом.
- Неактивная прошивка перемещена в `archive/firmware-not-used` с явным запретом на использование.
- Одноразовые генераторы/patch-скрипты перемещены в `archive/ci-migrations`.
- Build log исключён из Git и остаётся downloadable CI artifact.
- Старые APK удалены из вершины ветки, кроме текущих и явно выбранных rollback-сборок; восстановление возможно из Git-истории.
- CI создаёт контрольные суммы текущих APK.

## Критерий следующего релиза

Новый номер приложения допускается только при изменении его APK. Следующий функциональный релиз HomeSmoke должен быть не ниже 2.6.17, Remote — не ниже 2.4.7. Документальная уборка в этой ревизии не меняет версии 2.6.16/2.4.6.
